# ValutaTrade Hub

Консольное учебное приложение для работы с валютным портфелем и просмотра курсов. Покупка и продажа здесь являются учебными операциями.

## Установка и запуск

Нужны Python 3.12 или новее и `uv`. В папке проекта выполните:

```bash
uv sync
uv run python main.py
```

После запуска появляется приглашение `ValutaTrade>`. Команды приложения вводятся после него. Для выхода введите `exit`.

## Структура проекта

- `valutatrade_hub/core/` — модели валют, пользователи, кошельки, портфели и основные операции.
- `valutatrade_hub/infra/` — настройки и работа с JSON-файлами.
- `valutatrade_hub/parser_service/` — получение курсов из внешних API, обновление кэша и история измерений.
- `valutatrade_hub/cli/` — консольные команды.
- `data/` — локальные данные приложения.
- `logs/` — локальные журналы операций и обновления курсов.

## Команды приложения

```text
register --username ИМЯ --password ПАРОЛЬ
login --username ИМЯ --password ПАРОЛЬ
show-portfolio [--base ВАЛЮТА]
buy --currency ВАЛЮТА --amount КОЛИЧЕСТВО
sell --currency ВАЛЮТА --amount КОЛИЧЕСТВО
get-rate --from ВАЛЮТА --to ВАЛЮТА
update-rates [--source coingecko|exchangerate]
show-rates [--currency ВАЛЮТА] [--top ЧИСЛО] [--base ВАЛЮТА]
exit
```

Пример последовательности:

```text
register --username student --password example123
login --username student --password example123
buy --currency EUR --amount 2
show-portfolio
sell --currency EUR --amount 1
get-rate --from EUR --to USD
```

Покупка и продажа меняют баланс только кошелька выбранной валюты. Сумма в USD показывается для оценки; кошелёк USD при этих операциях не списывается и не пополняется.

## Курсы и локальный кэш

Пока `data/rates.json` отсутствует, основные команды используют фиксированные учебные курсы. После появления файла они читают курсы из локального кэша. Срок актуальности задаётся параметром `rates_ttl_seconds` в разделе `[tool.valutatrade]` файла `pyproject.toml`; сейчас это один час.

Команда `update-rates` запрашивает курсы у CoinGecko и ExchangeRate-API. Можно выбрать только один источник, например:

```text
update-rates --source coingecko
```

Parser Service сохраняет последние курсы в `data/rates.json`, а историю измерений — в `data/exchange_rates.json`. Каждый файл заменяется целиком после подготовки нового содержимого. Если один источник недоступен, данные другого всё равно могут сохраниться. Если не ответил ни один источник, прежний кэш не заменяется пустым.

Команда `show-rates` читает локальный кэш без обращения к API. Примеры:

```text
show-rates
show-rates --currency BTC
show-rates --top 2
show-rates --base EUR
```

При устаревшем курсе команда `get-rate` пытается обновить кэш через Parser Service, а затем повторяет чтение.

## Доступ к API

Ключ ExchangeRate-API задаётся через переменную окружения `EXCHANGERATE_API_KEY`. При необходимости ключ бесплатного плана CoinGecko Demo задаётся через `COINGECKO_API_KEY`. Ключи нельзя записывать в исходный код, README, JSON-файлы данных или Git.

Если ключ ExchangeRate-API не задан, этот источник сообщит об ошибке; обновление через другой доступный источник может продолжиться. Реальный доступ к API зависит от условий сервисов и доступных лимитов.

## Журналы и настройки

Покупки, продажи и ошибки этих операций записываются в `logs/actions.log`. Работа Parser Service записывается в `logs/parser.log`. Журналы автоматически ротируются по размеру.

Пути к данным, срок актуальности курсов и путь к журналу операций находятся в разделе `[tool.valutatrade]` файла `pyproject.toml`.

Периодическое обновление можно запустить отдельно:

```bash
uv run python -m valutatrade_hub.parser_service.scheduler
```

Планировщик работает до остановки процесса и по умолчанию повторяет обновление раз в час. Для остановки нажмите `Ctrl+C`.

Локальные данные, журналы и файл `.env` исключены из Git.

Запись также находится в файле `demo.cast`. Она показывает регистрацию, вход, обновление курсов, покупку и продажу BTC, просмотр портфеля и курса, а также обработку ошибок недостатка средств и неизвестной валюты.

Для локального воспроизведения:

```bash

```

Файлы `data/users.json`, `data/portfolios.json`, `data/rates.json` и `data/exchange_rates.json` создаются приложением при работе и не добавляются в Git. Для демонстрации используется только учебный пользователь и учебный пароль.
